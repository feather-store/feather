# Feather end-to-end benchmarks — 2026-11-08

Apple M1 (8 cores, 16 GB), macOS, Python 3.12. Working tree of
`docs/readme-v0.22` (0.21.0 + the unreleased 0.22 changes, time travel
included), default settings: fsync on (plain `fsync`, not `F_FULLFSYNC`),
`ef=50`. Latencies are wall-clock milliseconds per call, one caller at a time
unless a row says otherwise. Raw JSON: `bench/results/e2e_20261108/`.
Reproduce: `benchmarks/full_suite.py`, `benchmarks/e2e_latency.py`,
`benchmarks/api_bench.py`, `python -m bench run longmemeval ... --split dev`,
`python -m bench.locomo run --memory index`.

## 1. An agent turn, end to end (live models)

120 LoCoMo dev questions, sequential: embed the question (gemini-embedding-001,
3072-d, live), `hybrid_search` k=30 over the conversation's turns, render
(~5.3k chars), answer with gpt-4o-mini via OpenRouter (all 120 served by
OpenAI). Cost $0.028.

| stage | p50 | p95 | p99 | max |
|---|---:|---:|---:|---:|
| embed question (Gemini API) | 504 | 663 | 838 | 7,490 |
| **Feather `hybrid_search`, in-process** | **1.3** | **5.5** | **11.0** | 13.0 |
| Feather `hybrid_search` via Cloud API (HTTP, `RemoteDB`) | 5.8 | 9.4 | 19.3 | 30.0 |
| render context | 0.2 | 0.4 | 1.1 | 2.2 |
| LLM answer (gpt-4o-mini, OpenRouter) | 846 | 1,221 | 1,674 | 1,863 |
| **total** | **1,352** | **1,853** | **2,350** | 9,183 |

Feather is 0.15% of the turn. The embedding call is 37% of it and owns the
worst tail (one 7.5 s call). The retrieval p99 is the first query of each
conversation, which builds that DB's BM25 index.

### Contradiction (dev worlds, 20 trials × 8 people × 5 attributes)

When a fact about someone changed, does the current value reach the context,
and does the reader answer with it? Dense search (gemini), k=10, 1,500-token
budget; reader gpt-4o-mini, 40 packets per row.

| how memory is written | current value in context | stale values / packet | reader correct (in order / shuffled) |
|---|---:|---:|---:|
| free-text notes | 97-99% | 2.0 | 85% / 85% |
| notes, no valid time | 97% | 1.9-2.0 | 85% / **25%** |
| keyed facts (`AgentMemory.facts`) | 100% | 0 | 98% / 98% |
| items + `valid_at` | 97-99% | 2.0 | 85% / 85% |
| notes + keys | 100% | 2.0 | **100% / 100%** |

Keyword-only search (BM25) puts the current value in the context 73-84% of
the time for notes, 100% for keyed facts.

### Poisoning (planted "SYSTEM OVERRIDE" memories of untrusted origin)

| surface | defended: reaches prompt as instruction | obeyed by gpt-4o-mini, undefended | obeyed, defended |
|---|---:|---:|---:|
| `PacketBuilder` with a query | 0% | 25/25 (100%) | **0/25 (0%)** |
| `PacketBuilder`, hot set | 0% | 19/20 (95%) | 5/20 (25%) |
| `Pocket.hot_text()` | 0% | 8/20 (40%) | **15/20 (75%)** |

The defence keeps poison out of every binding slot and renders it as quoted
data (0% "as instruction", 0 forged headers), and that stops the model in
query packets. In `hot_text()` it does not: the model followed quoted poison
in 15 of 20 replies, more than undefended. Small n (20), one run — but it is
the one result here that says a shipped defence does not hold.

## 3. Vector recall on real embeddings

33,849 deduplicated gemini-embedding-001 vectors (3072-d, from the LongMemEval
and LoCoMo caches), 1,000 held out as queries, exact top-10 by brute force.

| ef | recall@10 | p50 | p99 |
|---:|---:|---:|---:|
| 10 | 0.937 | 0.23 | 0.53 |
| **50 (default)** | **0.995** | 0.60 | 0.89 |
| 100 | 0.998 | 1.06 | 1.65 |
| 200 | 0.999 | 1.78 | 2.68 |

The engine suite's synthetic 768-d Gaussian clusters give 0.58 at ef=50 —
in 768 dimensions every point of such a cluster is nearly equidistant, so
that figure measures the data, not the index. Use the table above.

## What the numbers say

1. **Feather is not the bottleneck of an agent turn** (0.15%). The embedding
   API call is 37% of it and the worst tail; the LLM is the rest.
2. **Recall at the default `ef=50` is 0.995 on real embeddings**, which
   holds CONTRACTS.md §1 ("≈ 0.99 at the default ef"). (An earlier draft of
   this report took the default to be 10, from a stale line in CLAUDE.md;
   `DEFAULT_EF` is 50.)
3. **BM25's first search is 1.95 s and 82 MB per process** on real text.
4. ~~**Tombstones cost tail latency**: 10% forgotten records take search p99
   from 0.4 to 13.9 ms until `compact()` (or `set_auto_compact`).~~
   Corrected 2026-11-10: not reproduced. With the CPU warm before each
   measurement, 100k x 768: p99 0.51-0.92 ms with no deletes, 0.67-1.01 ms
   with 10% forgotten, 0.54-0.98 ms after `compact()`. A run after a few
   seconds idle shows 4-21 ms p99 with or without deletes (cores clocked
   down): the 13.9 ms was that, not the tombstones.
5. Time travel adds nothing measurable to saves or opens; its cost is disk
   (a kept file is the whole DB as it was).
6. **Quoting untrusted memory does not stop gpt-4o-mini in `hot_text()`**
   (75% obeyed, defended); it does in query packets (0%).
7. Write facts with keys when they can change: 98-100% current answers
   versus 85% for free-text notes, 25% for shuffled notes without valid time.

## Harness bug found

`bench/locomo.py:1106` (`_answer_and_judge`) writes `"select": select` into
the run summary, but `select` is not one of its parameters: every
`bench.locomo run` crashes after answering and judging, before the summary
is written. The per-question records are complete, so this report scores
them with `bench.locomo rescore`. Fix: pass `select` through `_run` →
`_answer_and_judge`.

`bench run longmemeval` (bench/scenarios/longmemeval.py) does not cache
embeddings (only `bench.lme_retrieval` does): every end-to-end run re-embeds
its haystacks — 49,683 turns, ~12M tokens, ~$1.9 for the 100 dev questions,
the bulk of that run's cost.

## Cost of this report

About $3 in all, estimated from token counts (these harness paths do not all
print their spend): LongMemEval dev ~$3 (embeddings ~$1.9, gemini-2.5-flash
reader ~$1, judges), LoCoMo dev ~$0.15, the live latency run $0.028
(OpenRouter's own figure), contradiction and poisoning readers a few cents.

`python -m bench.suite` exits before running anything: it asks
`bench.contradiction` for the "notes + extracted keys" variant without
`--extract` (bench/contradiction.py:606). The two evals were run directly.
